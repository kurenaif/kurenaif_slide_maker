# 教材を編集するときの約束

新しい教材は `templates/html-lesson/` を `lessons/<lesson-id>/` にコピーして作り、`storyboard.md` を台本・画面仕様の正本にする。HTML/CSS/JavaScriptを直接編集し、Markdownから画面を生成しない。

この資料は口頭説明・動画編集で補足することを前提にする。画面は図を中心にし、見る人が「今、どこを見ればよいか」を迷わないように作る。

## 各ページの主題

- 作り始める前に「このページで伝えること」を一文で決める。黄色にするのは、その主題につながる領域・操作・参照。
- 大見出しは内容を具体的に表す。「〜すると？」より「〜で生じる不具合」「〜の管理方法」のようにする。
- 細かな数値・式・アドレスは、そのページの主題でなければ通常の白文字にするか発表メモへ移す。
- 同じ意味の図やラベルを二重に置かない。たとえばユーザー領域を別の箱で再掲する代わりに、元の図の該当箇所へ矢印を向ける。
- 情報が多い場合はページか操作を分ける。説明していない側は必要に応じて薄く表示する。
- フラグ、サイズ境界、ポインタの意味などの事実は教材ごとに対象のバージョン・前提を調べる。このテンプレートの模式図から実装仕様を推定しない。

## 配色

既定の `midnight-dark` は紺の背景、青系の面、白い文字、金のアクセント。`classic-light` を明示的に選ぶ場合は既存の明るい配色を使う。テーマ名は `storyboard.md` とHTMLの `data-theme` で一致させる。以下の色指定は `midnight-dark` の方針。ベース60・サブ30・アクセント10は構図上の目安であり、厳密なピクセル比率ではない。比率を満たすために装飾を増やさない。

| 役割 | トークン | 色 |
| --- | --- | --- |
| 背景 | `--paper` | `#19263B` |
| パネル | `--surface` | `#213149` |
| 主要な文字 | `--text` | `#F1EFE9` |
| 補助の文字 | `--muted` | `#A9BAD0` |
| 主題・注目先 | `--gold` | `#E3B968` |
| 使用中の領域 | `--used` | `#30445E` |
| 空き領域 | `--free` | `#426782` |
| 段階のある対応色 | `--class-1`〜`--class-4` | 青→紫→赤 |

- 要素名A、B、Cや種類が異なるという理由だけで色を増やさない。push/popが黄色でも、中の文字を無関係に黄色にしない。
- **青→赤のグラデーションは、各箱を単色で塗り、隣り合う箱の色を徐々に変える意味。** 箱の中に連続したグラデーションを描かない。
- stackの色は深さ・位置に対応する。Cを取り出した場所にDを入れたら同じ色。分類では見出し・ノード・対応先を同じ色にする。
- 塗りと通常の枠線の色相を揃える。黄色枠は意図した強調のときだけ使う。
- 空き領域は深い青＋薄い斜線＋白文字。管理リストのノードにも同じ表現を使う。色と斜線を使い分けるためだけに別のルールを増やさない。
- 水色の淡い背景に黒字は使わない。`#2C425E` の大きな面も既定にしない。
- 管理先のパネル全体を強い青で塗りつぶさない。使用中／再利用待ちの違いは名前・位置・領域の斜線でも示す。
- コードのシンタックスハイライトは使ってよい。実行行・説明中の行は金の目印で図の注目箇所と対応させる。
- 逆向きリンクbkは点線。方向の情報を色だけで伝えない。

キャラクターの衣装との組み合わせを想定した色だが、衣装画像から厳密に抽出した色ではない。キャラクターなしでも画面が成立することを優先する。

## Formal Witchとテーマ比較

`formal-witch` は白黒の魔女衣装（[公式衣装紹介](https://kurenaif.github.io/)の Formal Crypto Witch Costume）を参考にしたテーマ。衣装デザインは祝く月さん、モデリングは082さん。衣装の画像自体は同梱しない。以下はスライドの読みやすさを優先した解釈色であり、画像からの厳密な抽出値ではない。

| 役割 | 色・表現 |
| --- | --- |
| 図面の背景 | チャコール `#222125` |
| 見出し帯・本文の文字 | パールホワイト `#f5f1ef` |
| 見出し帯の文字 | 墨色 `#29262d` |
| 主題・矢印 | 明るいブロンズ `#d3b58a` |
| 白地の強調 | 濃いブロンズ `#795b38` |
| 分類 | 暗い紫からくすんだ赤紫への単色段階 |

白い見出し帯と暗い図面で衣装のコントラストを表現し、細い線と菱形を少量使う。見出しには明朝体を使い、図中のラベルは読みやすいゴシック体を保つ。図の中にフリルや編み上げを増やさず、意味のある主題に金系のアクセントを使う。

`examples/formal-witch/` は配色・参照・状態変化の3ページを持つテーマサンプル。テンプレートと全サンプルの「テーマ」選択で、`midnight-dark` / `classic-light` / `formal-witch` を切り替えられる。ページ・図・アニメーションは作り直さず、その場で配色を変更する。

選択はURLの `theme` に反映され、再読み込みやURL共有でも復元される（例: `?theme=formal-witch&step=1&cue=1`）。URLに有効な指定がない場合はHTMLと台本で指定した既定テーマを使う。選択によって既定テーマのファイル自体は書き換えない。切り替えは共有の `core/themes.js`、操作部のスタイルは `ui/theme-picker.css`。

## 説明の順序とアニメーション

- 入場時の自動再生は禁止。右キー1回でひとつの説明単位を見せて停止する。
- 動作中の右キーは、その動きの完了位置で停止。次の説明まで飛ばさない。
- 左キーで決定的に巻き戻せるようにする。前進回数で値を加算するなど、再描画の回数に依存する実装を避ける。
- 状態変化と参照を混ぜない。「Aが再利用待ちになる」を先に見せ、その後「管理側がAを指す」を別の操作で示す。
- 一方向の矢印は始点から伸ばす。両端に矢印を持つ一本の線は中央から両端へ伸ばす。
- 矢印の先端を早く表示しない。参照先の黄色枠は、矢印が届いてから描く。
- fd一周を1回、bk一周を次の1回で見せる。ルート全長に対して一度だけイーズイン・イーズアウトを適用し、各区間で止まらない。
- 点線の模様は描画中も維持する。補助リンクを加えるなら、その説明も別の操作に分ける。
- 全体の速度は基準に対して1.5倍。`duration: 1500` は実時間で約1秒となる。
- 処理全体の地図のように最初から見せるほうが説明しやすい図では、静的な矢印も認める。全部を機械的にアニメーション化しない。
- 連続再生は任意。メモを開いたとき、タブを隠したときは停止し、ページを離れたら描画を破棄する。
- OSの「動きを減らす」設定でも初期状態で待つ。右キーを押すたびにひとつの完成状態へ切り替える。

## シーンの追加

教材の `lesson.js` の `slides` に次の構造を追加する。`id` はシーンを識別する一意の文字列。URLは従来どおり0始まりの `?step=`、ページ内の完了した動きの数は `&cue=` で表す。

```js
{
  id: 'example', chapter: '概要', title: '伝えたい内容がわかる大見出し',
  notes: '口頭で補う内容。画面に必要ない詳細はここへ。',
  mount(root, onChange) {
    root.innerHTML = diagram('図の代替説明', `...SVG...`);
    return createCueMotion({
      cues: [{ duration: 900 }, { duration: 1500 }],
      onChange,
      render(index, progress) {
        const first = cueProgress(index, progress, 0);
        const second = cueProgress(index, progress, 1);
        // index=-1は初期状態。それぞれの進行度だけから図全体を再現する。
      },
    });
  },
}
```

共通APIは通常のスクリプトとして読み込んだ `window.SlideKit` から取得する。`createLessonPresenter({ slides })` がキー操作、サイズ調整、URLを管理する。

動かないページなら `cues: []` とし、`render` で初期表示だけを作る。最後のcueが終わった次の右キーで次のページへ移る。

矢印は `createArrow(path)` を一度生成し、`arrow.paint(ease(progress))` で描く。両端が矢印の線には `createArrow(path, { centre: true })` を使う。SVGの `marker-start` と `marker-end` は作者が指定する。

循環リンクは、循環する順番のパスを `createArrowCycle([path1, path2, ...])` に渡す。`cycle.paint(progress)` は内部で全体にイージングするため、外側で再度 `ease()` をかけない。矢印のパスは作成後に形を変えない。形を変更する場合は古い矢印を破棄して作り直す。

既存のシーンはDOMごと交換され、時計の `destroy()` が呼ばれる。追加のタイマーやイベントリスナーを作る場合は `destroy()` で確実に解除する。可能な限り共通の時計だけを使う。

## 保存前の確認

- 1980×1020で、見出し・図・操作ボタンが重ならず画面内に収まる。
- 390px幅ではページ全体が横にはみ出さず、図の中を必要に応じてスクロールできる。
- 主題になるラベルが大きく、補足を読まなくても関係がわかる。
- 初期表示、1回進む、動作中に進む、戻る、最後まで進む、ページを移る、URLを開き直す操作を確認する。
- 参照の矢印が届く前に強調枠が現れない。fdとbkを別々に説明できる。
- HTML/CSS/JavaScriptが完成品。このリポジトリではビルド不要。`index.html` を直接開き、`storyboard.md` の完成条件と照合する。


## 収録と配布

基準はブラウザの表示領域 **1980×1020**。16:9と同一ではないため、録画・編集で別の比率を指定した場合はそのサイズでも確認する。幅851px以上では基準の構図全体を収める。発表メモを開いている間は通常のスクロールになる。

1980×1020のとき、主要領域は x=44〜1936、y=28〜937。図だけなら y=196〜937が目安。操作ボタンはその下に置き、切り出しを容易にする。大きな外枠やキャラクター用の目立つ四角は置かない。

スマホでHTMLを直接見る場合は、必要に応じて図の中だけ横スクロールする。動画は横向きの視聴を基準に大きな要点を優先する。小さい縦向き動画の中ですべての注釈まで読ませる設計にはしない。

色・内容・操作を変えたときは、この方針と対象教材の `storyboard.md` も更新する。数式が必要な教材だけMathJaxを読み込む。`createLessonPresenter` はページ変更とロード時に再タイプセットを呼ぶ。非同期で数式を追加する場合は教材側でも `MathJax.typesetPromise()` を呼ぶ。
